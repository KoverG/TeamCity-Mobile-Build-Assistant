## 1. Назначение продукта

TeamCity Mobile Build Assistant сокращает количество действий, необходимых сотруднику для получения мобильной сборки и отправки ссылки на неё в Telegram.

Пользователь работает в уже открытой и авторизованной вкладке TeamCity. Browser Extension встраивает в страницу собственную панель, помогает выбрать нужную сборку, находит APK или IPA в artifacts и отправляет защищённую TeamCity-ссылку в личный чат пользователя с Telegram bot.

Главные продуктовые принципы:

1. Минимум лишних переходов и кликов.
2. Пользователь всегда сам выбирает Project, OS, Environment и конкретный build.
3. Продукт не выбирает «самую актуальную сборку» и ничего не отправляет автоматически.
4. TeamCity остаётся источником авторизации и прав доступа к builds и artifacts.
5. TeamCity credentials и Telegram Bot Token не попадают в код Browser Extension.
6. Поиск ориентирован на конечный APK/IPA, а не на фиксированную структуру каталогов или `.nupkg`.
7. Telegram-функции централизованы на backend, чтобы впоследствии единообразно применять подписки и ограничения.
8. Продукт разрабатывается как публичный open-source-проект и не зависит от конкретной компании, TeamCity-доменов, project IDs или соглашений об именовании.
9. Данные реальной компании и её TeamCity-инсталляции не должны попадать в исходный код, конфигурацию по умолчанию, tests, fixtures, документацию, logs или историю Git.

Open-source-безопасность является обязательным продуктовым ограничением. Функция не считается готовой, если для её работы нужно зафиксировать в repository реальный URL, имя проекта, идентификатор build configuration, branch, artifact path либо другой tenant-specific параметр. Такие данные обнаруживаются во время работы или задаются пользователем во внешней локальной конфигурации.

## 2. Пользователи и предпосылки

MVP предназначен для небольшой группы сотрудников, которым уже предоставлен доступ к нужным проектам TeamCity.

Пользователь должен:

- быть авторизован в TeamCity в браузере, где установлено расширение;
- быть авторизован в TeamCity на мобильном устройстве, если он открывает защищённую ссылку из Telegram;
- один раз связать Browser Extension со своим Telegram account через bot pairing.

Продукт не создаёт отдельные логины и пароли и не участвует в TeamCity authentication flow.

## 3. Клиентский интерфейс

### 3.1. Формат клиента

MVP — Browser Extension для Chromium-браузеров:

- Google Chrome;
- Microsoft Edge;
- Яндекс Браузер.

Расширение работает внутри страницы TeamCity. Плавающая кнопка открывает встроенную правую панель. Отдельный сайт в MVP не нужен.

### 3.2. Основной выбор

Панель содержит каскадный выбор:

```text
Project → OS → Environment → Build
```

Поддерживаемые OS:

- Android;
- iOS.

Поддерживаемые environments:

- Development;
- Staging;
- Preview;
- PreProduction;
- Production.

Project и build configurations загружаются динамически из TeamCity REST API в пределах прав текущего пользователя. OS и Environment определяются отдельным классификатором build configurations.

### 3.3. Выбор build

MVP показывает только builds, одновременно удовлетворяющие условиям:

- `status:SUCCESS`;
- `state:finished`;
- build относится к выбранной build configuration;
- учитываются все доступные branches.

Для build отображаются как минимум:

- публичный номер;
- TeamCity build ID;
- branch;
- дата завершения;
- состояние поиска APK/IPA.

Пользователь может:

- выбрать build из полученного списка;
- ввести номер build вручную в контексте выбранных Project, OS и Environment.

Номер build рассматривается как строка и ищется внутри конкретной build configuration.

### 3.4. Запоминание выбора

Пользователь явно управляет checkbox `Запомнить выбранные значения`.

Если checkbox включён, Browser Extension сохраняет текущие:

- Project;
- OS;
- Environment.

Если checkbox выключен, выбор живёт только в текущей UI-сессии. Регистрация на backend для этого не нужна: данные хранятся локально в browser profile.

### 3.5. Onboarding

При первом запуске показывается обязательное уведомление:

> Для получения списка сборок необходимо войти в TeamCity в этом браузере. Для скачивания ссылки из Telegram необходимо войти в TeamCity на устройстве, где будет открыта ссылка.

Пользователь подтверждает:

> Я понимаю, что ссылки защищены авторизацией TeamCity.

Принятие сохраняется вместе с версией текста. При изменении существенных условий версия увеличивается, и уведомление показывается повторно.

## 4. Состояния TeamCity-сессии

Extension не выполняет вход в TeamCity.

Если REST API недоступен из-за отсутствующей или истёкшей сессии, UI показывает отдельное состояние с понятным действием:

> Авторизуйтесь в TeamCity и повторите запрос.

Технический adapter должен различать как минимум:

- HTTP `401/403`;
- redirect на login page;
- HTML login page вместо ожидаемого JSON/XML;
- сетевую ошибку;
- timeout;
- недостаток прав на конкретный project/build/artifact.

## 5. Поиск APK/IPA

Поиск начинается только после того, как пользователь выбрал конкретный build.

Правила:

- для Android целевой файл — `.apk`;
- для iOS целевой файл — `.ipa`;
- основной поиск использует bulk listing TeamCity и получает список файлов минимальным количеством GET-запросов;
- расширение фильтрует `.apk`/`.ipa` без учёта регистра и использует выданный TeamCity `contentHref`; если поле отсутствует, применяется проверенный runtime fallback `repository/download`;
- если bulk listing конкретной версии TeamCity не раскрывает archive/container nodes, запускается ограниченный по времени, глубине, количеству запросов и параллелизму fallback traversal;
- поддерживаются обычные директории и раскрываемые TeamCity archive/container nodes;
- структура каталогов заранее не предполагается;
- `.nupkg` не считается конечным результатом и является лишь одним из возможных контейнеров.

Результат поиска:

| Количество кандидатов | Поведение |
|---|---|
| 0 | Build остаётся виден, действия блокируются, показывается `Artifact не найден` |
| 1 | Artifact считается однозначно найденным |
| 2 и более | Негативный сценарий MVP: действия блокируются, показывается ошибка неоднозначной конфигурации |

Автоматически выбирать один файл среди нескольких запрещено.

## 6. Действия с найденным artifact

Для однозначно найденного APK/IPA доступны:

- скопировать прямую защищённую TeamCity-ссылку;
- открыть/скачать artifact;
- отправить сообщение в личный Telegram chat через backend.

Ссылка использует TeamCity `repository/download` и остаётся защищённой TeamCity authentication. Backend не проксирует и не скачивает файл в MVP.

Artifacts могут быть удалены TeamCity cleanup policy. Поэтому историческая ссылка из Telegram не гарантируется как вечная. Продукт не копирует artifacts в собственное хранилище.

## 7. Telegram

### 7.1. Личный чат

Каждый пользователь получает сообщения в личный чат с bot. Общая группа и Telegram topics не используются в MVP.

Telegram-сообщение содержит:

- Project;
- OS;
- Environment;
- номер build;
- дату build;
- branch;
- прямую защищённую TeamCity-ссылку.

История отправок в UI расширения не реализуется: пользователь видит её в Telegram.

### 7.2. Pairing

Полноценной регистрации нет. Пользователь один раз выполняет минимальный pairing:

1. Нажимает `Подключить Telegram`.
2. Extension получает одноразовый pairing code.
3. Открывает `https://t.me/<bot>?start=<pairing-code>`.
4. Пользователь нажимает `Start`.
5. Backend связывает Telegram user/chat с конкретной установкой Extension.
6. Extension получает device token.

Один Telegram account может иметь несколько активных Extension devices. Одна команда создаёт одно Telegram-сообщение независимо от количества устройств. Повторы команд блокируются idempotency.

### 7.3. Подписка

В MVP все успешно paired пользователи автоматически получают entitlement:

```text
SendTelegramBuildLink = Active
```

Платежей в MVP нет. Архитектура предусматривает централизованную проверку entitlement перед каждой Telegram-отправкой. Позднее источник entitlement можно заменить на платную подписку, trial, корпоративную лицензию или ручное управление.

Подписка может отключить только функции, проходящие через backend. Она не может отозвать собственные TeamCity-права пользователя.

## 8. MVP scope

В MVP входят:

- установка Extension в режиме разработчика;
- встроенная панель TeamCity;
- определение текущего TeamCity origin;
- проверка TeamCity session;
- динамическая загрузка двух исследованных мобильных проектов и их build configurations;
- классификация OS/Environment;
- список `SUCCESS + finished` builds из всех branches;
- ручной поиск по номеру build;
- явное запоминание Project/OS/Environment;
- bulk-first поиск APK/IPA с ограниченным рекурсивным fallback;
- обработка 0/1/нескольких кандидатов;
- копирование и открытие TeamCity artifact URL;
- Telegram pairing;
- личные Telegram-сообщения;
- бесплатный `Active` entitlement;
- idempotency, rate limiting и базовый аудит;
- развёртывание backend на изолированных ресурсах существующего VPS.

## 9. Не входит в MVP

- отдельный публичный сайт;
- кнопка возле каждой строки build в TeamCity;
- множественный выбор builds;
- объединение builds разных environments;
- поиск всех builds одной задачи/ветки как отдельный UX;
- автоматический выбор последнего build;
- поддержка нескольких TeamCity-инсталляций в UI;
- платные подписки и платежный провайдер;
- Telegram groups/topics и project roles;
- отправка самого APK/IPA в Telegram;
- собственное долговременное хранение artifacts;
- история отправок в Extension;
- установка IPA через TestFlight/MDM/`itms-services`;
- Firefox и Safari.

## 10. Следующие итерации

Приоритетные направления после MVP:

1. Кнопка `Отправить в Telegram` возле build в TeamCity UI.
2. Фильтр и поиск по feature branch/task key.
3. Множественный выбор builds и environments.
4. Поддержка других TeamCity origins и classification profiles.
5. Управление подключёнными devices.
6. Платные entitlements.
7. Отдельный Web UI при появлении сценариев, которым тесно внутри TeamCity.
